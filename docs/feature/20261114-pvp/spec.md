# PvP 玩家对战（IR #11 第二部分）

> 对应 Issue：[EXIST-D/PixelCampus#11](https://github.com/EXIST-D/PixelCampus/issues/11)
> 规范：[docs/feature/spec.md](../spec.md)
> 状态：已确认（2026-11-14），待开工

## 1. 背景与目标

现在的战斗只有三种：野生精灵、校园猫友谊赛、训练家 NPC。**玩家之间不能对战**。

本批目标：

- 玩家可以邀请另一位玩家进行 1 对 1 精灵对战。
- 服务器权威：双方行动都由服务器校验和结算，客户端只显示。
- 复用现有战斗引擎（`src/shared/battle.ts`）和能力等级 / 状态异常 / 非伤害招式 / 技能库。

**不做**：匹配大厅、排位、观战、多人乱斗、跨世界对战。

## 2. 用户与场景

- 玩家 A 在公共世界（或好友世界）找到玩家 B，点 B 的学生证 →「对战」。
- B 收到邀请（30 秒内回应），接受后双方进入战斗。
- 双方各自选精灵、出招，服务器记录双方队伍、结算回合、推事件给双方。
- 战斗结束：双方各自看到结算；胜者获得少量奖励（可选），双方不掉精灵、不回校门。

## 3. 功能需求

| 编号 | 需求 | 优先级 |
|---|---|---|
| R1 | 邀请：点对方学生证 →「对战」，对方 30 秒内接受/拒绝 | P0 |
| R2 | 队伍检查：双方都要有至少 1 只能战斗的精灵 | P0 |
| R3 | 战斗前选首发（默认队伍第 1 只），战斗中可以换人 | P0 |
| R4 | 双方行动都由服务器校验，按速度/优先级排出手顺序 | P0 |
| R5 | 每回合双方都提交后才结算；超时（60 秒）自动替该玩家选择「跳过」 | P0 |
| R6 | 断线：30 秒内重连可继续，超时判负 | P0 |
| R7 | 逃跑：任一玩家可以逃跑，逃跑方判负（与 PvE 不同） | P0 |
| R8 | 战斗结束：双方各自结算，不传送、不掉精灵，血量保留 | P1 |
| R9 | 同一时间只能有一场 PvP | P0 |
| R10 | 只能在同一个世界、且双方距离在视野内才能邀请 | P0 |
| R11 | 双方都同意后才能开始（邀请 + 接受） | P0 |
| R12 | 战斗中不能打开精灵面板整理队伍（沿用现有约束） | P0 |

## 4. 正向场景

- **P1.** A 点 B 学生证选「对战」，B 收到邀请提示，选「接受」后双方进入战斗。
- **P2.** 双方都看到对方队伍（血条、上场精灵），并且看到自己的队伍。
- **P3.** 双方各自出招，服务器按速度排出手顺序，事件同时推给两边。
- **P4.** 我方精灵倒下且有活着的队友 → 进入换人阶段，选一只上场。
- **P5.** 对方精灵倒下且有活着的队友 → 对方进入换人阶段，我方看到「对方正在选择……」。
- **P6.** 一方全部倒下 → 另一方胜利，双方看到结算。
- **P7.** 任一方点「逃跑」→ 逃跑方判负，战斗结束。
- **P8.** 一方超时未出招 → 自动跳过这一回合（对方照常行动）。
- **P9.** 一方断线 30 秒内重连 → 回到战斗，看到当前状态。
- **P10.** 双方距离超出视野 / 不同世界 / 任一方在战斗中 → 邀请被拒。

## 5. 反向 / 异常场景

- **N1.** 客户端**绝不能**自行结算伤害或判定胜负。
- **N2.** 服务器**绝不能**接受不存在的战斗 id、错误的回合号。
- **N3.** 服务器**绝不能**接受非参战玩家的行动。
- **N4.** 同一时间**绝不能**有超过一场 PvP。
- **N5.** 邀请**绝不能**跨世界（公共 / 个人 / 好友世界）。
- **N6.** 被邀请方离线 / 在战斗中 / 在宿舍 / 钓鱼中**绝不能**收到邀请。
- **N7.** 战斗中**绝不能**打开精灵面板整理队伍。
- **N8.** 超时**绝不能**导致战斗卡死：必须自动跳过或判负。
- **N9.** 断线重连**绝不能**让玩家重复结算或获得额外回合。
- **N10.** 逃跑方**绝不能**继续行动或获得奖励。
- **N11.** 双方**绝不能**同时被判定胜利。
- **N12.** 玩家可见文字**绝不能**用 `innerHTML`。

## 6. 数据 / 协议

### 6.1 新消息（C→S）

```ts
| { t: 'pvp_invite'; uid: number }
| { t: 'pvp_reply'; uid: number; accept: boolean }
| { t: 'pvp_act'; bid: string; turn: number; a: PvpAction }
| { t: 'pvp_leave' }
```

### 6.2 新消息（S→C）

```ts
| { t: 'pvp_invite'; uid: number; name: string; ms: number }
| { t: 'pvp_state'; bid: string; turn: number; phase: 'choose'|'swap'|'over'; me: PvpSide; foe: PvpSide; result?: 'win'|'lose'|'fled'; ev: BEvent[] }
| { t: 'pvp_end'; bid: string; result: 'win'|'lose'|'fled'|'timeout'; msg: string }
```

- `PvpSide`：`{ name: string; lead: number; squad: { sp; lv; hp; max; sh? }[]; stages: ...; status: ... }`
- 复用 `BEvent`，不新增事件类型。
- **协议版本升级**：新消息是 additive，`PROTOCOL_VERSION` 不升；如果改动 `mon_bt` 则另议。

### 6.3 存档

- **不写存档**：PvP 结果不持久化（可选的胜负计数以后再加）。
- 战斗中的血量变化**不回写**玩家存档（PvP 是友谊赛，打完双方恢复原样）。

## 7. 界面

- 邀请：复用现有「交易邀请 / 组队邀请」的弹窗样式。
- 战斗界面：复用 `BattleUi`，把「野生 / 训练家」换成「对方玩家名字」，对方卡片显示对方精灵。
- 结算：显示胜负 + 「离开」。

## 8. 服务端

- `PvpSession`：持有双方队伍、回合、行动、超时计时。
- 隔离：PvP 会话和 PvE 战斗会话互斥。
- 不能放在 `Mons` 里（那个按单个 key 存），建议单独 `server/pvp.ts`。

## 9. 验收标准

- [ ] P1–P10 可用
- [ ] N1–N12 不违反
- [ ] 双方事件顺序一致
- [ ] 超时、断线、逃跑都有正确处理
- [ ] `npm test` / `tsc` / `vite build` / 服务端测试全绿
- [ ] 测试服双人 E2E 通过

## 10. 不在范围

- 匹配大厅、排位、评分
- 观战
- 多人（3 人以上）混战
- 跨世界对战
- PvP 奖励 / 成就 / 每日任务（留给 #10）

## 11. 已确认的设计（5 个问题）

| # | 问题 | 结论 |
|---|---|---|
| 1 | 邀请权限 | **任何人可邀请**（公共世界 / 好友世界内）；只能邀请同世界、视野内、不在战斗中的玩家 |
| 2 | 奖励 | **不给校园币**；胜负计数 / 成就留给 #10 |
| 3 | 血量 | **统一满血**，打完**不写回存档**（PvP 是友谊赛） |
| 4 | 等级平衡 | **无限制**（自由对战）；以后可加「同级对战」选项 |
| 5 | 道具 | **不能用零食包**捉对方精灵；只允许技能 / 换精灵 / 逃跑 |
