## 2026.11.12（战斗深度 2A-3：非伤害招式）更新内容
**新增：命中 / 闪避接入命中判定**
- 命中率 = 基础命中 × 命中/闪避等级倍率，夹在 5%–100%；必中招式（命中 100%）不受影响。
**新增：非伤害招式（回复 / 变化 / 保护）**
- 回复：打盹（回满 + 自睡 2 回合，清除毒 / 灼伤、保留麻痹，PP 5）、自我再生（1/2，PP 5）、小憩（1/4，PP 10）、吸取（伤害的 50% 回血，PP 10）。
- 变化：剑舞（攻 +2）、铁壁（防 +2）、高速移动（速 +2）、瞪眼（对方防 −1）、影分身（闪避 +1）、烟雾（对方命中 −1）。
- 保护：守住（本回合免伤；连续使用成功率 ×0.5，最低 25%；换人 / 用其他招式中断）。
- 菜单显示「威力 —」+ 效果说明；满血使用回复招会提示并照常消耗 PP。
- 同一机制多套名字：开放包按属性各给风味招式；猫系一套「老吴」风味（哈气护体 / 打盹 / 瞪眼 / 影步 / 磨爪 / 舔毛）。
**调整：状态可以共存**
- 每只精灵可同时有多个状态；睡眠与冰冻互斥，中毒 / 灼伤 / 麻痹可两两共存，也可与睡 / 冻同时存在。
- 行动判定：睡眠 / 冰冻优先，否则才掷麻痹 25%。
- 捕捉加成：睡眠 / 冰冻 / 麻痹任一 ×2。
**测试**：新增 `tests/battle-moves.test.ts`（14）、`tests/integration/battle-ui-moves.test.ts`（3）；公开全量 66 文件 643 通过 / 3 跳过；真实 E2E（本地客户端 + 测试服）菜单显示「威力—」+ 效果说明。

**新增：钓鱼全服播报**

## 2026.11.11（战斗深度 2A-2：状态异常）更新内容
**新增：状态异常**
- 中毒（每回合 −1/8）、灼伤（−1/16，物理威力减半）、麻痹（速度减半，25% 无法行动）、睡眠（1–3 回合）、冰冻（每回合 20% 解冻）；沿用经典规则。
- 只在本场战斗：按精灵 id 记在 `Battle` 里；换人保留、倒下清除、战斗结束丢弃，**不进存档**。
- 毒 / 灼伤可以把野生精灵打死，算正常胜利（给经验、记见过）。
- 睡眠与冰冻互斥；同种状态不叠加、不刷新；毒 / 灼伤 / 麻痹可共存。
- 睡眠 / 冰冻时捕捉成功率 ×2（`catchChance` 可选参数），夹在 5%–95%。
- 睡 / 冻 / 麻痹（25%）时**完全不能行动**（不送出招、换人、扔球、逃跑）；UI 禁用按钮并提示「无法行动……」，等服务器推进。
- 老吴系列按属性附带状态：火 10% 灼伤、电 10% 麻痹、冰 10% 冰冻、毒 30% 中毒、幽灵 10% 睡眠。
**测试**：新增 `tests/battle-status.test.ts`（17）、`tests/integration/battle-ui-status.test.ts`（4）；全量 94 文件 1123 通过 / 5 跳过；`tsc` / `vite build` 绿。

## 2026.11.6（第二批：首次访问流量减半——图集 WebP、Phaser 分包、brotli、字体切片；2026-11-06 已部署）更新内容
起因：线上出口带宽被压到很低（约 1 Mbps）时，一次完整的首次访问要下 6.3 MB，玩家半路刷新、进不去。先把"一次访问要下多少"压下来（和限速是否解除无关，有用）。
**调整：首次访问下载量 6.3 MB → 约 2.95 MB（−53%）**（按出生点、秋季、支持 brotli 的浏览器估算；实际以浏览器网络面板为准）
- **图集、地面块、室内底图、小地图改用无损 WebP**（`npm run assets:webp`，`npm run assets` 和 `npm run deploy` 都会自动跑，已转过的跳过）：像素与 PNG **逐点一致**（转换时逐张校验）。建筑图集 2.7 MB → 1.45 MB；地面块约小 25%（噪点纹理，有损反而更大，所以不用有损）。PNG 仍保留在 dist 里（地图编辑器、`?world=` 对照版、部署时正在线上玩的旧页面还在要 PNG）。精灵内容包 `mons/` 不动。
- **brotli 预压缩**：`npm run deploy` 构建后对 js/css/json 生成 `.br`（`tools/assets/precompress.ts`），服务器看到浏览器支持就直接发，比 gzip 再小 15%~30%（`world.json` 78→50 KB，我们的 JS 188→148 KB），服务器不占 CPU；不支持的浏览器仍走 gzip。`.br` 比原文件旧时不会被使用。
- **Phaser 单独打包**（`vite.config.ts` 的 `manualChunks`）：引擎 1.2 MB（压缩 264 KB）几乎不变，文件名哈希不变，玩家缓存后**每次部署只需重新下载我们自己的代码（约 150 KB）**，不用每次再下一遍引擎。服务器把 `assets/xxx-哈希.js|css` 都按永久缓存发。
- **字体切片**：中文像素字体原来整包 553 KB 且启动时要等它；现在按字切成三片（`tools/assets/font-slices.py`，规则在 `src/ui/fonts.css`）：常用字 + 游戏里用到的字约 85 KB（首屏只要这一片）、其余 GB2312 汉字约 105 KB、生僻字约 436 KB，浏览器只下载页面上实际出现的字所在的那片。玩家昵称/气泡/猫名里的生僻字：DOM 文字自动重排，Phaser 文字（头顶昵称牌、气泡）在切片下完后重画一次（`src/ui/glyphs.ts`）。emoji 等字体里没有的字不会触发下载。完整字体源文件挪到 `tools/assets/fonts/`，不再随网页发布。
- **启动时少预载地面块**：出生点 ±1600 像素（12 块）改成 ±800（6 块，和流式加载范围相当），进入世界前少等约 0.8 MB；其余仍按视野流式加载。
- 没动：游戏规则、协议、玩家数据；画面与之前完全一致（地面/建筑像素逐点相同）。
**部署注意**：这批改了服务端的静态文件逻辑（`server/static.ts`），要和客户端一起部署（`npm run deploy` 本来就会）。首次部署 rsync 要多传一批 `.webp`（约 57 MB）。

**修复：玩家多了以后服务器周期性卡顿（存档改为增量落盘）**
- 原因：玩家档案（`players.json`）一天天变大（已到 10MB、近 7000 个档案），而存档每次都把**全部**档案整份序列化再写盘，单次要卡住服务器 0.2 秒以上，有人在线操作时几乎每 2 秒一次，表现为移动回弹、操作延迟、掉线；序列化时的临时内存还会逼近进程内存上限。
- 现在：平时只把「内容变了的档案」追加写进增量日志 `players.json.log`（实测 7000 个档案时一次约 2 毫秒，原来整份写约 50–180 毫秒）；日志超过 16MB（或快照 2 倍）、超过 10 分钟、关服、换身份码时，才写一份完整快照并清掉日志。启动时先读快照再重放日志，最后一行被截断也能恢复。`players.json` 的格式不变。
- 另有轮转复查：每轮顺带重新比对一小批档案，防止有代码绕过 `get()` 直接改了对象而漏存。
- **备份注意**：增量日志里可能有最近几分钟的改动，手动备份要把 `players.json` 和 `players.json.log` 一起拷（或先 `systemctl restart pixelcampus` 让它合并成快照）。
